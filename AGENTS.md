# reverse-skill — Platform-Neutral Repository Entry

This repository is a **security-task skills router package** (reverse engineering, penetration testing, and security analysis). `RULES.md` is the single source of truth for the behavior chain.

## Routing

When a user task matches security or reverse-engineering keywords:

1. Use `skills/MASTER-ROUTING.md` or the platform entry to reach PRIMARY:
   - Windows: `powershell -NoProfile -ExecutionPolicy Bypass -File skills/scripts/master-route.ps1 -Hint "<task>"`
   - Linux / macOS / Kali: `bash skills/scripts/master-route.sh --hint "<task>"`
2. For an ambiguous route, read the full `skills/routing.md` matrix (target type, user intent, and toolchain).
3. `skills/config/routing.json` is the single source of truth. Change routes only there.

## Authorization Gate (Hard Requirement)

- Before acting on any target, initialize `work/<case>/scope.md` for the current analysis project:
  - Windows: `powershell -File skills/scripts/case-init.ps1 -Hint "<task>"`
  - Linux / macOS / Kali: `bash skills/scripts/case-init.sh --hint "<task>"`
- Use the `offline-sample` preset for a local offline sample. Enter ACT only when `auth.status=granted` and an explicit sample exists.
- Do not enter ACT until `auth.status=granted` and a valid `network_profile` or offline sample is ready. `case-guard --force` and `-Force` must not bypass this hard gate.
- Evidence chain: `skills/ops/evidence-finding-path.md`. Role map: `skills/ops/role-map.md`.

## First Run

`skills/tool-index.md` is a gitignored generated file. Run the platform command before first use:

```text
Windows:           powershell -NoProfile -ExecutionPolicy Bypass -File skills/scripts/refresh-tool-index.ps1
Linux / macOS:     bash skills/scripts/refresh-tool-index.sh
Kali:              bash kali/scripts/refresh-tool-index.sh
```

If a tool is missing, use the same-platform bootstrap: Windows `skills/scripts/bootstrap-reverse.ps1`, Linux / macOS `skills/scripts/bootstrap-reverse.sh`, or Kali `kali/scripts/bootstrap-reverse.sh`. Use the manifest and do not guess paths.

## Tests (Run After Changes)

```text
Windows / PowerShell (routing regression reads routing-benchmark.json):
  powershell -NoProfile -ExecutionPolicy Bypass -File skills/scripts/test-routing.ps1
  powershell -NoProfile -ExecutionPolicy Bypass -File skills/scripts/verify-routing-coherence.ps1
  powershell -NoProfile -ExecutionPolicy Bypass -File skills/scripts/smoke.ps1

Linux / macOS routing parity:
  bash skills/scripts/test-routing.sh
  bash skills/scripts/test-bootstrap-manifest.sh
```

## Client Boundary

- Keep the routing core, tests, and tool manifests independent of any specific AI client.
- Claude Code, Codex, Cursor, OpenCode, and other clients may connect only through their adapters. Do not make a client the repository's default identity or a core configuration dependency.
- `skills/INDEX.md` is generated by `extract-summaries.ps1` from all `SKILL.md` files. Do not hardcode client or module counts.
